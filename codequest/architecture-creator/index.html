Static files, serverless everything, one credentialed identity per family, and AI behind a proxy. Built to cost pennies until a cohort proves it should cost more.

The keystone

One format decision removes the hardest problem
Kids make single HTML files.
So the browser is the sandbox.

No containers, no server compute per kid, no code ever executing on our infrastructure. A project is a static file on a CDN. The “Cursor for kids” rig collapses to an editor, a and an AI pane. Every 2026 build already follows this format.

Layer by layer

The choices

Identity

One credential per family

The Parent holds the only real login. Makers are , not accounts. Players need nothing at all.

Domains

Two domains, on purpose

The app domain holds login, the rig and upload. The distribution domain serves the gallery and every kid's project, cookie-free and static. Kids' uploaded content with the app it was uploaded through.

Spaces

Spaces, distinct from accounts

The unit of work is a space, not an account: a project container a maker can hold several of, and a team can . Accounts are who you are; spaces are what you're building. Publishing promotes a space to the distribution domain.

The rig

Editor, iframe, AI pane

CodeMirror in the browser, the file saves to S3, the preview renders live. The AI pane talks only to our proxy: per-kid daily , a locked kid-tuned system prompt, Bedrock so the without touching the client, and guardrails on both directions.

Knowledge

RAG over their world, not the internet

Bedrock Knowledge Bases over the course content plus the kid's own project file. “Why doesn't my jump work” gets answered against their code and our curriculum.

Courses & assessment

The publish pipeline is the LMS

Submitting coursework is publishing a project. Assessment is the approval queue plus feedback. Belts are a profile field. Course content is static pages. The calendar is an . No LMS gets built.

Human chat

Phased on purpose

AI-to-kid on day one: it's 1:1 with a machine we control. Kid-to-kid comes later, cohort-scoped with adult visibility, never open DMs. Moderation load at pilot scale must stay near zero.

Money

Stripe, known territory

Parent subscription on Billing, event tickets on Checkout, the fee-offset from the engagement page is a coupon applied at the 16:30 convert.

The order of work

Phasing

1
Before any cohort

S3 + CloudFront, secret-link upload via presigned POST, pending→approve, manifest gallery seeded with the eight existing builds, refs in URLs, Stripe payment links. Proves the loop at ~$44/yr.

2
When a real cohort runs

Cognito Parent accounts, DynamoDB proper, the rig, the AI proxy with quotas and guardrails, engagement counts.

3
When retention is proven

The app as a wrapper over the same web code (push, cohort presence, App Store legitimacy), full RAG assistant, cohort tooling — and only then any talk of richer runtimes.

The standing rule

Build the feature when doing it manually starts to hurt, and not a week before. Coins are a spreadsheet. Remix is copying a folder. The cost of this business is coaches and venues, never servers.
