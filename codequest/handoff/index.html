Moving the media

The script needs curl, python3 and the aws cli. No jq. Run it from the package directory. Dry run needs no AWS credentials at all, so it is safe to run first.

# see what exists, transfer nothing
./sync-media.sh --bucket YOUR_BUCKET --dry-run

# the two groups the MVP actually needs, about 3.5 MB
./sync-media.sh --bucket YOUR_BUCKET --groups brand,avatars

# everything, about 128 MB
./sync-media.sh --bucket YOUR_BUCKET --groups all --profile codequest

It downloads to a temp directory and checks each file is non-empty before uploading, so a half fetched video never lands in your bucket. Re-running is safe. Uploads set the right content type and a long immutable cache header.

Consent before convenience

These are real children's faces and image consent sits with each household, not centrally. Use them inside CodeQuest surfaces. Ask before anything external or public facing, and prefer keeping faces behind authentication until per child consent is something the product records.

The one thing to read first

Ship the stylesheet globally, never inside a component scoped <style> block. Astro attaches its scoping attribute at build time to elements that exist in the template, so elements created at runtime with createElement never receive it and scoped rules silently do not apply. Every class in this system is a plain global class for exactly that reason.

// once, in a layout
import '../styles/codequest-design-system.css';

There is also a test idea in CLAUDE.md worth three lines of your time: assert on getComputedStyle rather than the DOM for critical controls, because from the DOM a rule that failed to apply and a rule that was never written look identical.
